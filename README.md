# Андреа — расширения для SpeedFix v4

Точка входа осталась прежней: **`SCP-079-Derenguh_Andrea_SpeedFix_v4.py`**. Редактор `.ai2d` также можно запустить отдельно. Второго приложения или второго экземпляра GGUF для Telegram нет. Где изменены входные файлы и что скопировать вручную — см. [сборочный лист](ASSEMBLY.md).

## Установка и первый запуск

1. Сохраните отдельную копию `aria_config.json`, файлов `aria_*memory.json` и всей старой рабочей папки. Остановите все процессы v4.
2. Положите оба исходных `.py` и все `scp_*.py` рядом. Запускайте из прежней рабочей директории: v4 ищет конфиг и часть старых файлов относительно текущего каталога.
3. Создайте окружение `python -m venv .venv` (Python 3.10+). Активируйте его. Колёса **с транзитивными зависимостями**, для своей ОС, CPU и версии Python, подготовьте отдельно.
4. Установите: `python -m pip install --no-index --find-links=wheels -r requirements.txt`. На Linux нужен рабочий графический сеанс с системными библиотеками Qt (OpenGL, EGL, xkbcommon и D-Bus). Для проверки без окна: `python -m pip install --no-index --find-links=wheels -r requirements-test.txt` и `python -m pytest -q`.
5. Запустите `python SCP-079-Derenguh_Andrea_SpeedFix_v4.py`. Укажите **свою локальную Gemma_IT-uncensored GGUF** в настройках. По умолчанию используются CPU, mmap, `n_ctx=3072`, пакет 256; прогрев — один токен. Ускоритель использует ручные маркеры Gemma, не требует исправного шаблона в GGUF.
6. Для речи с Piper нужен локальный исполняемый `piper` и `aria_workspace/voices/ru_RU-irina-medium.onnx` **с соседним `.onnx.json`**. Можно задать `piper_model_path`. Голоса не скачиваются. Для Silero укажите доверенный локальный пакет в `tts_model_path`, для XTTS (`tts_backend="xtts"`) — `xtts_model_dir` и `xtts_speaker_wav`; нужны установленные офлайн совместимые torch/Coqui. Системный резерв — espeak(-ng) или pyttsx3. Пины необязательных лёгких интеграций в `requirements-optional.txt`. Для OGG нужен локальный `ffmpeg` с libopus.
7. Откройте свой `.ai2d` с размеченными глазами и ртом. Без рига нечего анимировать. `avatar_enhanced=false` возвращает стандартное окно v5.3.
8. Автономность включается вручную в существующем UI, после перезапуска выключена. `proactive_enabled=false` отключает инициативу планировщика; `tts_enabled=false` — озвучку в UI, `telegram_voice_replies=false` — голосовые ответы. Изменения JSON вносите при закрытом приложении.
9. Для полностью автономного рабочего места оставьте Telegram выключенным, `web_enabled=false`. Если нужен Telegram, запустите **свой локальный Bot API сервер** на `127.0.0.1:8081` (порт — `telegram_local_api_port`), задайте `telegram_owner_id`, токен и вручную запустите мост. Сам Telegram-транспорт требует связи с Telegram и не является офлайн-чатом. Прямого обращения к публичному Bot API в приложении нет. Токены не добавляйте в Git.

## Память и совместимость

| Где (относительно `CFG['workspace']`, обычно `aria_workspace`) | Содержимое |
|---|---|
| `short_memory/*.jsonl` | Реплики с контекстом и временем. Имя — хэш безопасный для Windows. `get_context()` сохраняет формат `role/content/time`. TTL по умолчанию 72 часа не касается локального владельца и его личного Telegram-чата. |
| `long_memory/diary_*.md`, `index.json`, `topics.json`, `facts.jsonl` | Долговременный дневник, индекс и факты. Не очищаются таймером. |
| `creator/profile.json`, `creator/v4.json` | Структурированный профиль и перенесённые данные старого профиля. |
| `emotions_v2.json`, `presence.json`, `thoughts_dedup.json` | Эмоции, присутствие и фильтр повторов. Старое `emotions.json` остаётся для fallback. |
| `summaries/`, `tts_cache/`, `perf.jsonl` | Производные саммари, WAV и замеры времени/RSS. |

Мигратор запускается **до** глобальных конструкторов памяти v4. После переноса создаёт `migration_v2.json`. Оригиналы сохраняются в `*.migrated.bak` рядом с исходниками. Для используемых старым UI редактируемых списков и профиля остаётся рабочая JSON-копия. Не удаляйте маркер в попытке запустить перенос ещё раз. Для отката восстановите весь снимок до миграции, включая сессии. Файлы памяти, логи и голосовой кэш не зашифрованы — это личные данные.

## Ограничения исполнения

- `accelerator_enabled=false` возвращает оригинальный маршрут llama.cpp. Ускоритель использует KV уже загруженного контекста llama.cpp, не хранит второй снимок KV размером в гигабайты. Время первого фрагмента включает обработку промта. Контекст не выбрасывает два последних обмена, чтобы любой ценой вместить огромный ввод: если обязательная часть не помещается, запрос отклоняется.
- **10,5 ГиБ — целевой бюджет, а не измеренный максимум.** Размер GGUF, архитектура KV, графический драйвер и TTS влияют на пик. Проверка размера файла до загрузки не заменяет измерения на той машине. Для первого запуска отключите речь, не загружайте XTTS и проверьте RSS в `perf.jsonl`/диспетчере задач. При нехватке памяти уменьшите `n_ctx` или выберите меньшую квантизацию **той же** Gemma.
- Модель не получает shell или полноценный интерпретатор Python. `terminal` принимает фиксированные диагностические команды, `python_executor` — числовые присваивания и арифметику. Опасные инструменты требуют отдельного подтверждения на конкретный вызов. В Telegram подтверждения допускаются **только в личном чате числового ID владельца**. Буфер и снимок экрана исполняются в Qt-потоке. `allowed_apps` — словарь «имя → абсолютный путь к доверенному исполняемому файлу».
- Без новых модулей v4 сохраняет старые классы и доступные ветки исполнения. Потенциально опасные операции при отсутствии подтверждения или безопасного исполнителя закрыты, а не возвращаются к `shell=True`.
