# Андреа 4.1.0: настройка и диагностика

**Обновление поверх v4.** Закройте приложение и сделайте копию `aria_config.json` и рабочей папки. Замените Python-файлы комплектом одной версии, включая `scp_diagnostics.py`. Не удаляйте память, `.migrated.bak`, маркер миграции и ваш GGUF. Рабочий каталог и команда прежние: `python SCP-079-Derenguh_Andrea_SpeedFix_v4.py`. В заголовке должно быть **4.1.0**. Это версия программы; веса модели обновление не меняет.

## Первый диалог на CPU

1. Откройте **Настройки → Модель**, проверьте путь. Для первоначальной проверки на 12 ГБ установите контекст 3072 (или 2048 при нехватке памяти). Старое значение 4096 не меняется без вашего согласия. Больший контекст — не ускорение.
2. В секции **Ускорение** оставьте короткий промт, адаптивный предел и раннюю остановку включёнными. Оставьте модельные саммари **выключенными**, лимит ответа **0**. Нажмите **Загрузить модель**. Настройки сохранятся; загрузчик дожидается освобождения общего движка. Не загружайте вторую копию приложения.
3. Строка «Готова» показывает имя **фактически загруженного файла**, внутреннее имя GGUF, CPU, размер контекста и активный шаблон. Выбор файла без загрузки сам по себе модель не переключает.
4. Напишите `Привет, как ты?`. Короткий режим не отправляет каталоги инструментов и не запускает поиск для приветствия; профиль и эмоции остаются в промте. Пользовательский системный промт сохраняется. Для обычных задач инструменты доступны как раньше.

| Настройка | Что меняет и когда полезна |
|---|---|
| Ручной шаблон Gemma и ускоритель | Включено: собственный маршрут с ограниченным контекстом, журналом фаз и настройками ниже. Выключено: штатный `create_chat_completion` llama.cpp. Для GGUF с другим шаблоном попробуйте штатный маршрут; при пустом `chat_format` библиотека выбирает его сама. |
| Короткий промт | Уменьшает обработку **до первого токена** на простых приветствиях. Не подменяет ответ заготовкой. |
| Кэш ответов | Возвращает сохранённый результат для идентичного собранного промта и параметров. Эмоции, время и история могут изменить ключ. Отключите для замеров чистой генерации. |
| Адаптивный предел | Дополнительно ограничивает число **выходных** токенов по типу запроса. Не сокращает время чтения промта. |
| Ранняя остановка | Прерывает повтор токенов. Отключите при преждевременном конце кода или списка. Конец хода Gemma обрабатывается отдельно. |
| Прогрев | Один пробный токен при загрузке. Переносит часть задержки на старт, не ускоряет сам процессор. |
| Саммари моделью | Компрессия истории дополнительным запросом к той же модели. На медленном CPU лучше оставить выключенной: остаётся текстовое сокращение. |
| Лимит ответа | Секунды на пользовательский запрос **в ускорителе**, включая prefill. 0 — не прерывать по времени. Для автоматических мыслей/фоновых запросов остаются отдельные лимиты. |

После изменений нажмите **Загрузить модель**, иначе экземпляр ускорителя продолжит использовать параметры предыдущей загрузки. Сравнивайте режимы на одной GGUF, с одинаковым вопросом и чистым тестовым диалогом, а не удаляя долговременную память.

## Журналы: что смотреть

В настройках нажмите **Открыть журнал features.jsonl**. Файл находится в `CFG["workspace"]` (обычно `aria_workspace`), одна строка — одно JSON-событие; ротация по 1 МиБ, три резервных файла. В этом журнале нет текста реплик, содержимого буфера, голосовых данных или токенов Telegram. Старый `aria.log` и файлы диалогов могут содержать личную информацию — проверяйте их перед отправкой.

- `app/startup`, `memory/migration_check`, `model/loaded`: доступные расширения, проверка миграции, реальная модель, потоки, контекст, шаблон и переключатели.
- `chat/prepare → llm/request → prefill_start → first_chunk → complete`: число входных токенов, лимит выхода, время до первого фрагмента и общее время. Если долго нет `first_chunk`, задержка до первого вывода, а не в TTS. `cache_hit` вместо `prefill_start` означает, что вычисление пропущено. На штатном маршруте GGUF подробных фаз ускорителя нет.
- `llm/failed`: причина и длительность. **`llama_decode returned 2` ровно через заданный лимит** согласуется с остановкой из callback. Теперь истечение лимита показывается отдельно, контекст модели сбрасывается, ошибка не записывается как ответ Андреа. Если код 2 повторяется при лимите 0, это другая диагностика: проверьте совместимость вашей сборки llama.cpp с архитектурой файла, попробуйте штатный шаблон, уменьшите контекст и приложите `model/loaded`, `prefill_start`, `failed` и traceback.
- `events`, `emotion_engine`, `presence`, `autonomy`, `memory`, `context_manager`: тип события, операции памяти, решения дедупликатора, время обработки. `tools/confirmation` показывает разрешение/отказ, не аргументы команды. `avatar_enhancer/address` — обращение к аватару. Кадры и содержимое скриншотов не логируются.
- `tts`: попадание в WAV-кэш, запуск синтеза/проигрывания, системный резерв. Если нет Piper с локальным ONNX и нет Silero, на Windows используется установленный системный голос через pyttsx3. Отсутствие Silero само по себе не ошибка LLM.
- `perf.jsonl` — показатели успешных генераций (RSS, время, токены/с). `aria.log` — исходные исключения и сообщения прежних компонентов. Нет скачивания модели или отправки журналов разработчику.
